New package: usage credits extracted from Lore Spawner's lore tokens. Ships SQL and Hasura metadata templates (`hasura/`, rendered by `kk-hasura sync`) for a priced usage ledger, balances, a monthly dollar-funded free pool, admin grants, Stripe purchases with auto-refill and a user's own model key, all row-locked and server-only; `createCredits` (`admit`, `beforeCall`, `onUsage`) and a store over an injected executor; pure pricing, pool, billing and grant rules; Stripe purchases (`/stripe`), price feeds (`/feeds`) and screens on `@kaperkunde/ui` (`/ui`).

Before the first release (from review): a call is admitted only when the price in force can charge the kinds it will use (`UNPRICED` otherwise), a price sets `input` and `output` together, a spend that fails leaves the row pending for `spendPending` (run it from a cron), and kind fallbacks are resolved onto each price version (`derived`) so changing one never reprices a call. Every table name is a `table_<name>` variable (`usage_table` now defaults to `{{prefix}}usage`), with a README section on adopting existing tables. Only two-decimal currencies are sold in; auto-refill has no default currency; abandoned refill claims count toward the monthly maximum; refill failures reach the user as a kind in the package's words; `checkout.session.async_payment_succeeded` is credited; the server may insert own-key ledger rows through Hasura; price feeds take their provider explicitly (`priceFeeds`, replacing `defaultFeeds`).
